# 3D Gaussian Splatting 论文拆解

这份笔记对应 Kerbl 等人的 *3D Gaussian Splatting for Real-Time Radiance Field Rendering*。先记住一句话：它不再把一个场景表示成“输入坐标、输出颜色和密度”的神经网络，而是直接把场景存成很多可以移动、缩放、旋转、变色的半透明椭球。

## 1. 它要解决什么问题

给定同一静态场景的许多照片，以及每张照片的相机位置，目标是在没有拍过的位置生成一张合理的新照片。这叫新视角合成。

早期 NeRF 会对每条像素射线反复查询神经网络并做体渲染，质量高但慢。3DGS 的选择是把计算提前到训练阶段：训练出一组显式高斯后，渲染时像图形学 rasterization 一样投影和混合，所以很快。

## 2. 一个高斯到底存了什么

第 i 个高斯的可学习状态是：

- 中心 `mu_i`：它在三维世界的坐标。
- 尺度 `s_i=(sx, sy, sz)`：椭球三个轴的半径。
- 旋转 `q_i`：四元数，决定椭球朝向。
- 不透明度 logit `o_i`：经过 sigmoid 后才是 0 到 1 的 alpha。
- 球谐系数 `f_i`：决定从不同观察方向看到的 RGB。

椭球的三维协方差是：

```text
Sigma = R(q) diag(sx^2, sy^2, sz^2) R(q)^T
```

这就是为什么编辑器里显示的是椭球而不是球：`R` 和三个不同的尺度让它能贴合细长物体、边缘或平面。

## 3. 三维椭球如何变成屏幕上的椭圆

相机先把世界点变到相机坐标系：

```text
x_cam = W x_world + t
u = fx * x_cam / z_cam + cx
v = fy * y_cam / z_cam + cy
```

`(u, v)` 是高斯中心在屏幕上的像素坐标。透视投影不是线性的，因此论文在高斯中心处用 Jacobian `J` 进行一阶近似：

```text
Sigma_2d = J W Sigma W^T J^T
```

`Sigma_2d` 是二维椭圆的形状。某个像素离中心越远，二维高斯值越小。

## 4. 为什么必须按深度排序

一个像素通常被多个半透明椭圆覆盖。离相机近的高斯先消耗透光率，远处高斯只能用剩下的透光率：

```text
alpha_i(p) = sigmoid(o_i) * exp(-0.5 * d_i(p)^T Sigma_2d^-1 d_i(p))
C(p) = sum_i [ c_i * alpha_i(p) * product_{j<i}(1-alpha_j(p)) ]
```

其中 i 从近到远。这个公式叫前到后 alpha compositing。若不排序，玻璃、遮挡边缘和物体前后关系都会错。

## 5. 颜色为什么用球谐函数

漫反射物体从各个方向看颜色差不多，但金属高光、玻璃反射会变。球谐函数把“观察方向 -> 颜色”的连续函数展开成有限个系数。

- SH 0 阶：恒定颜色。
- SH 1 阶：能表达线性方向变化。
- SH 3 阶：论文常用的 16 个系数，能表达更丰富但仍易计算的视角相关效果。

本项目从零阶颜色初始化，训练命令可创建三阶系数；高阶系数初始为零，随后由损失自动学习。

## 6. 训练为何需要增密和裁剪

固定数量的椭球无法同时覆盖平坦背景和细小纹理。论文用渲染损失对二维投影中心的梯度判断“哪里没拟合好”：

- 梯度大且高斯小：clone，复制一个高斯以增加局部容量。
- 梯度大且高斯大：split，用更小的子高斯替换它。
- opacity 很低：prune，删掉几乎无贡献的高斯。

这相当于模型在训练中自己决定哪里需要更多几何细节。

## 7. 论文的工程关键

朴素实现会让每个高斯检查每个像素，计算量是 `O(NHW)`。论文把屏幕切成 tile，只把会覆盖某个 tile 的高斯送到这个 tile，再在 tile 内排序、混合。真正高性能的版本还会把这套流程写成定制 CUDA 前向和反向 kernel。

本项目提供两套同公式后端：`reference` 便于核对数学；`tiled` 在 CUDA 张量上进行 tile culling，便于理解和训练小规模场景。它不是官方论文级的 fused CUDA kernel，因此不能把它的 FPS 和论文数字直接比较。
